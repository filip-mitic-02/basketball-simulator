# Perfect Season (repo name: 82-0-coach)

Draft 10 players from random historical NBA team-seasons (1950 to 2026), then coach them through a full
82-game season and the playoffs, possession by possession. Sign in with Google to save results and appear on the leaderboard.

- `public/` static game (engine, league, UI, `data.json`)
- `api/` Vercel serverless functions: Google OAuth, sessions, runs, leaderboard
- `lib/` shared server code (session, validation, db, http helpers)
- `schema.sql` Postgres schema
- `scripts/` data pipeline that builds `public/data.json` from Basketball-Reference style CSVs (not needed to run the site)
- `tests/` `npm test`

## Deploy on Vercel

1. Push this repo to GitHub and import it in Vercel (Framework preset: **Other**; no build command needed).
2. **Database:** in the Vercel project open Storage / Marketplace, add **Neon** (Postgres). It sets `DATABASE_URL`.
   Open the Neon SQL editor and run `schema.sql` once.
3. **Google OAuth:** Google Cloud Console > APIs & Services > OAuth consent screen (External; scopes: `openid`, `profile`),
   then Credentials > Create credentials > OAuth client ID > Web application.
   Authorized redirect URIs:
   - `https://YOUR-DOMAIN/api/auth/callback`
   - `http://localhost:3000/api/auth/callback` (local development)
4. **Environment variables** (Vercel > Settings > Environment Variables, see `.env.example`):
   `BASE_URL` (exactly your public URL, e.g. `https://82-0.example.com`), `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`,
   `SESSION_SECRET` (`openssl rand -base64 48`), `DATABASE_URL`.
5. Redeploy. Open the site and click "Sign in with Google".

Local development: `npm install`, copy `.env.example` to `.env`, fill it in, run `npx vercel dev`.

## Security model

See [SECURITY.md](SECURITY.md). In short: server-side OAuth code flow with PKCE, state and nonce; HttpOnly `__Host-` session cookie;
strict CSP and other headers; origin and header check on every state-changing request; parameterised SQL only;
scores recomputed on the server; per-user rate limits; the public leaderboard shows first name and last initial only;
users can delete their account and data from the Rules dialog.

## Data

`public/data.json` is generated by `scripts/prep.py` (+ `scripts/newseasons.py` for recent seasons from game logs).
Player statistics are factual data from public sources; see the sources' own terms before redistributing the raw CSVs (they are git-ignored).
Team crests and player avatars are generated SVGs, not real logos or photos.


## Anti-cheat architecture

Signed-in drafts and seasons are verified on the server (see SECURITY.md). Run this SQL once in Neon (it is in `schema.sql`):
the `drafts` table and the new `runs` columns `draft_id`, `verified`, `sim_version`, `log`. After changing `public/engine.js`,
`league.js`, `core.js` or `data.json`, bump `VERSION` in `public/core.js` and run `node scripts/update-sim-lock.mjs`.


## Rating model and balance

The rating on a card is paid for by measurable components (`CRED` in `public/engine.js`: shooting, passing, rebounds, steals, blocks,
turnovers, fouls). The game models each component explicitly, so shot quality uses `coreOf(player)`, the part of the rating the
components do not explain. Each component is calibrated so that a team-wide gain in it is worth what the rating credits it for
(`node scripts/measure-impact.mjs 12000` prints the measured effect next to the target). `node scripts/balance-check.mjs 160` plays
greedy drafts through full seasons and prints wins, titles and the league spread (best opponent about 61 wins, worst about 18).
Any change to the engine, league or data needs a new `VERSION` in `public/core.js` and `node scripts/update-sim-lock.mjs`.

When the version changes, clear old results (their logs belong to the old simulation):

    delete from runs;
    delete from drafts;

## Tactic fit

Offense and defense options are balanced so that none is better for every roster (measured: each averages about 0 pts/g across rosters, and swings by about +-2 pts/g depending on fit). `Report.tacticFit` (public/report.js) predicts the fit of Inside, Threes, Ball movement, Zone and Press from minute-weighted roster features and frames the best one per group as "Best fit". Tempo and Isolation get no verdict. After changing tactic constants, bump `Core.VERSION`, run `node scripts/update-sim-lock.mjs`, and refit the `FIT` coefficients.

## Signature traits

About 2% of player-seasons (rated 72+ with one rare, league-leading skill) carry a trait: Foul Magnet, Playmaker, Shot Eraser, Lockdown, Sniper, Glass Cleaner or Go-To Scorer. `Engine.traitOf` derives it from the player's own stats, so it never needs hand-curation, and it is cached from the original stats before the league opponents are stretched. A trait acts on the court beyond what the rating pays for (constants in `Engine.TR`); each is calibrated to about +2 pts/g for the team that has the star (`ablation: tests removed the star's trait`). Both user and AI teams use them. Changing `TR` needs a new `Core.VERSION` and `node scripts/update-sim-lock.mjs`.

## Interactive moments

Only in games you coach step by step; quick sims and "sim quarter" skip them. Each live game has a Matchup duel in the second and third quarters, plus Coach's Calls when the game calls for one: a close finish, overtime, four minutes without scoring, or an opponent run (10 unanswered points, or a net 10 over five minutes). At most six per game. Each is a pure function of the game state, answers are logged as op `M` and re-applied by the server replay, and an unanswered moment has no effect. The right read is worth about one point per game on average.

## Injuries and trades

Injuries: each of your games has a small chance (5.5% in the regular season, 2.5% in the playoffs) that one player is hurt, picked by minutes played, for 1 game (55%), 2 (40%) or 3 (5%). Only one player can be out at a time. Rolls come from their own seeded stream (`L.injR`), so they never change other results and the server replay reproduces them. An injured player is treated like a fouled-out player from the first whistle (`Engine.markOut`).

Trades: until game 55, at most two per season, from the hub. `Core.tradeOffers` returns three players within a few overall points of the one you give (the window widens if the market is thin), valid for the roster positions, from a pure function of season seed, trade count and player index. The log records `['tr', give, offer]` and the replay regenerates the offers and checks the choice. The new player takes the old one's slot, minutes and starter spot, and the traded player's season stats are kept in `L.tradedAway`.

## EuroLeague

A second competition, chosen on the menu. Rules live in `Engine.RULES.{nba,el}` (40-minute games, five fouls, 20 clubs, 38 games, top eight to best-of-five quarterfinals, then a neutral-court Final Four). Players come from `public/data-el.json`, built by `scripts/prep_el.py` from `data/euroleague/players.csv`, which `scripts/fetch-euroleague.mjs` downloads from the public EuroLeague API (run it locally; seasons 2000-2026). Runs, drafts and the leaderboard carry a `comp` column. After changing sim files, bump `Core.VERSION` and run `node scripts/update-sim-lock.mjs`.
